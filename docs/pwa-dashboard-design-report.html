Dumply Design Research · 2026-07

웹 대시보드 Top 30 사례 리서치
— Dumply PWA를 위한 디자인 제안

Todoist부터 Stripe, Duolingo, Finch까지 — 30개 서비스의 홈/대시보드 화면을 분석해 공통 모범 사례를 추출하고, "그냥 쏟아내면 알프레도가 정리해주는" Dumply의 웹버전(PWA)에 가장 적합한 대시보드 설계안을 제안합니다.

사례 30개 · 4개 카테고리 교차 패턴 분석 7건 Dumply 적용 권장안 + Top 10 우선순위
조사 방법 안내: 이 세션에는 Mobbin MCP 서버가 연결되어 있지 않아, Mobbin 공개 갤러리 링크·각 서비스 공식 문서/체인지로그·2025–26년 디자인 티어다운을 대상으로 한 웹 리서치로 동일한 조사를 수행했습니다. 카드마다 원본 출처 링크를 달았으며, Mobbin 스크린 갤러리는 시각 자료 확인용으로 병기했습니다 (예: Mobbin 웹 대시보드 패턴 갤러리, Duolingo Web).

요약 — 핵심 발견 5가지

① 홈의 두 철학: "시스템 계산형" vs "사용자 서약형"

Todoist·Linear·Monday는 마감·우선순위로 오늘 할 일을 자동 산출하고, Any.do·Sunsama·Trello Planner는 매일 아침 빈 보드에서 사용자가 직접 "오늘 이것만"을 담게 합니다. Dumply의 AI 트리아지(알프레도)는 두 철학을 결합할 수 있는 드문 위치 — AI가 제안, 사용자가 승인하는 구조가 최적입니다.

② 공통 스켈레톤: 사이드바+단일 콘텐츠, 모바일에선 바텀탭

30개 중 데스크톱 웹은 예외 없이 '접이식 좌측 내비 + 메인 영역(+필요시 우측 상세 패널)'. 모바일/PWA에선 사이드바가 최대 5개 항목의 바텀 탭바로 변환되는 것이 업계 합의 패턴입니다 (Vercel은 한손 조작용 플로팅 바텀바까지 도입).

③ 오버듀 처리가 곧 제품 철학

일괄 리스케줄(Todoist), 최상단 고정(ClickUp 4.0), 제안으로 격리해 죄책감 제거(Any.do) — 미룬 일을 다루는 방식이 서비스 성격을 결정합니다. "정리 걱정 말고 던져라"는 Dumply에는 Any.do식 안티-길트(anti-guilt) 접근이 정합적입니다.

④ 마스코트는 장식이 아니라 상태 표시기

Duolingo의 Duo는 행동에 따라 표정·아이콘까지 변하는 상태 머신이고, Finch는 홈 상단 40%를 펫 무대로 쓰며 태스크 완료가 펫의 에너지로 직결됩니다. 알프레도를 홈의 시스템 보이스(빈 상태·오프라인·축하·설치 유도)로 승격시키는 것이 차별화 핵심입니다.

⑤ 2025년, AI가 홈 화면에 올라왔다

GitHub 에이전트 태스크 모듈, Notion 3.0 Agents, Height의 자동 트리아지 — 최신 홈의 신모듈은 "내 AI가 한 일/하는 일"입니다. 알프레도의 MoSCoW 분류 결과를 '검토·승인' 형태로 홈에 노출하면 이 흐름의 선두 패턴과 일치합니다.

PART 1 · 태스크 관리 서비스

사례 01–08 — "오늘 뭘 할지"를 시스템이 계산해주는 계열

01

Todoist

태스크 관리

미니멀 투두의 표준 — Today 뷰와 "Todoist Zero"

레이아웃
접이식 사이드바 + 단일 칼럼 리스트. 같은 Today 데이터를 리스트/보드/캘린더로 재렌더링하는 레이아웃 스위처.
Today 개념
P1 태스크 빨간색 최상단 정렬, Overdue 섹션 + 원클릭 일괄 "Reschedule". 캘린더 레이아웃에선 미배정 태스크를 드래그해 타임블로킹하는 "Plan" 사이드바.
모범 사례
  • 자연어 Quick Add ("내일 10시 #프로젝트 p1")
  • 실행일(date) vs 마감일(deadline) 분리 + 7일 카운트다운 칩
  • 빈 Today = 일러스트 축하 화면 ("Todoist Zero")
Dumply 적용
덤프 입력창에 자연어 날짜 파싱을, 비운 Today 보드에 알프레도 축하 일러스트를.

출처: todoist.com/help · PWA 모범 사례로 자주 인용 (오프라인 지원)

02

TickTick

태스크 관리

3패널 클래식 + 습관·뽀모도로·아이젠하워 통합

레이아웃
아이콘 레일 + 사이드바 + 리스트 + 선택 시에만 열리는 우측 상세 패널. 별도 모듈: 캘린더·아이젠하워 매트릭스·포커스·습관.
Today 개념
스마트 리스트(Today/Tomorrow/Next 7 Days) + 오늘의 습관이 태스크 아래 체크 섹션으로 동거. 2×2 매트릭스 뷰로 긴급/중요 드래그 재분류.
모범 사례
  • 습관과 태스크를 한 화면에 — 데일리 서피스 단일화
  • 아이젠하워 매트릭스를 1급 뷰로 내장
  • Achievement Score·스트릭으로 가벼운 게이미피케이션
Dumply 적용
MoSCoW 매트릭스를 TickTick의 2×2처럼 드래그 재분류 가능한 뷰로 제공.

출처: help.ticktick.com · 웹/데스크톱/모바일 UI 일관성으로 호평

03

Asana

태스크 관리

위젯 홈 + 축하 크리처 — 딜라이트의 교과서

레이아웃
"Good morning, [이름]" 인사 헤더 + 드래그·리사이즈 가능한 위젯 그리드(My Tasks, Projects, People, 개인 메모장, Goals). 배경색 커스터마이즈.
Today 개념
Home(아침 브리핑용 대시보드)과 My Tasks(실행 리스트, Today/Upcoming/Later 섹션 자동 승급)를 분리.
모범 사례
  • 완료 시 유니콘·예티가 날아가는 랜덤 보상 축하 애니메이션
  • 홈에 개인 메모장(비정형 스크래치 공간) 배치
  • 시간대별 인사 + 통계 스트립
Dumply 적용
Must 태스크 완료 시 알프레도 축하 모먼트(랜덤 variant) — 변동 보상이 핵심.

출처: help.asana.com · zapier.com

04

ClickUp Home 3.0 / 4.0

태스크 관리

카드 캔버스 홈 — Overdue를 Today 옆에 고정하는 반(反)슬리피지 설계

레이아웃
드래그·리사이즈 카드 캔버스(My Work, Agenda, Recents, LineUp, 개인 리스트). 4.0에서 "Today & Overdue" 페이지 중심의 서브페이지 구조로 재편.
Today 개념
"로그인하면 오늘 할 일이 가장 먼저" — 오버듀를 Today 최상단에 병치해 즉시 리스케줄 유도. My Work 카드는 Today/Overdue/Next/Unscheduled로 그룹.
모범 사례
  • LineUp — 마감 로직과 무관한 소수 정예 "이것부터" 리스트
  • 카드별 설정 메뉴로 개인화
Dumply 적용
알프레도가 뽑은 "오늘의 3가지"를 LineUp 스타일 고정 카드로.

출처: help.clickup.com

05

Monday.com My Work

태스크 관리

색이 곧 언어 — 날짜 버킷 트리아지 테이블

레이아웃
좌측 패널 + 풀폭 테이블. My Work는 전체 보드 횡단 집계를 6개 날짜 섹션(Past dates/Today/This week/…)으로, 각 섹션에 카운트 배지.
Today 개념
순수 날짜 버킷 트리아지. 상태/날짜/우선순위 셀을 리스트에서 인라인 편집. 그룹 기준(날짜↔상태↔우선순위↔보드) 전환 드롭다운.
모범 사례
  • 채도 높은 상태 색상 필 — 읽지 않고도 훑어지는 진행 상태
  • 하나의 리스트, 여러 멘탈 모델(re-group 스위처)
Dumply 적용
MoSCoW 색상을 Monday처럼 "훑어 읽는 상태 언어"로 일관 적용 (이미 tokens.css에 기능색 존재).

출처: support.monday.com · 모바일 앱도 동일 날짜 그룹 유지

06

Linear

태스크 관리

키보드 퍼스트 + 시스템이 유지하는 포커스 순서

레이아웃
슬림 사이드바 + 고밀도 이슈 리스트(리스트/보드/분할 패널 전환). LCH 색공간 기반 테마 시스템 — 다크 모드의 업계 벤치마크.
Today 개념
"Today" 없음. My Issues가 긴급→SLA→블로커→현재 사이클 순의 하드코딩된 포커스 순서로 자동 정렬, 빈 섹션은 숨김. Triage는 외부 유입 이슈의 격리 검토소.
모범 사례
  • Cmd+K + 단축키로 마우스 없는 전체 조작
  • Triage: 워크플로 진입 전 격리 상태
  • 축하 없음 — 속도 자체가 보상이라는 철학
Dumply 적용
덤프 → 알프레도 분류 대기열을 Linear Triage처럼 "검토 후 승인" 단계로 모델링.

출처: linear.app/docs · 2019년부터 반응형 웹, PWA 설치 지원

07

Trello (2025 New Trello)

태스크 관리

Inbox + Planner — 보드 도구에서 개인 생산성 콕핏으로

레이아웃
Inbox(개인 캡처 칼럼) | Planner(주간 캘린더) | Board를 원하는 조합의 분할 패널로 병치. 좁은 화면에선 단일 패널로 접힘.
Today 개념
캡처 → 정리 → 실행 루프: 이메일/Slack에서 AI가 제목·마감·우선순위를 파싱해 Inbox로, Inbox 카드를 Planner 시간 슬롯에 드래그하면 그것이 곧 오늘 계획.
모범 사례
  • AI 파싱 유니버설 캡처
  • 실제 캘린더 이벤트 옆에 드래그 타임블로킹
  • 미러 카드로 개인/팀 중복 해소
Dumply 적용
Dumply의 "덤프"가 곧 Trello Inbox — 이미 같은 모델. 캘린더 병치 드래그 배치가 다음 단계.

출처: atlassian.com

08

Any.do My Day

태스크 관리

매일 아침 백지에서 시작하는 안티-길트 리추얼

레이아웃
가벼운 2–3존 레이아웃, Next 7 Days는 요일별 칼럼 칸반. 캘린더 패널 병치 가능.
Today 개념
My Day는 필터가 아니라 의식(ritual): 매일 아침 빈 상태에서 시작, 오버듀는 자동 유입되지 않고 AI "Smart Suggestions"로 제안 — 한 탭으로 수락/거절해 작고 실행 가능한 계획을 구성.
모범 사례
  • 오버듀를 Today에서 격리 — 죄책감 제거 설계
  • 완료 차임·계획 차임 등 오디오 마이크로 보상
  • 하루 끝 미완료 태스크의 부드러운 재계획 플로우
Dumply 적용
"던져놓고 잊어라" 철학과 가장 정합적인 레퍼런스. 알프레도의 아침 제안 = Smart Suggestions의 캐릭터 버전.

출처: support.any.do

PART 2 · 데일리 플래너 · 캘린더

사례 09–16 — "오늘"을 시간 축 위에 배치하는 계열

09

Sunsama

데일리 플래너

명상 같은 생산성 — 가이드형 아침 플래닝 리추얼

레이아웃
3패널: 내비 + 요일별 칼럼(kanban-of-days) + 우측 캘린더/통합도구 패널. 태스크를 캘린더 패널로 드래그해 타임박싱.
Today 개념
단계별 플래닝 마법사(~10분): 어제 미완료 검토 → 오늘 목록 구성 → 태스크마다 시간 추정 필수 → 워크로드 카운터가 임계 초과 시 경고 → 넘치면 내일로 이월. 저녁 셧다운 리추얼로 회고.
모범 사례
  • 플래닝을 빈 화면이 아닌 '흐름'으로 — 가이드 위저드
  • 시간 추정 합계 vs 임계치로 과약속 방지
  • 주간 회고 차트(채널별 시간)로 계획→실행→반성 루프 완성
Dumply 적용
알프레도가 진행하는 아침 브리핑 플로우(3단계 이내)로 경량화 도입.

출처: help.sunsama.com

10

Akiflow

데일리 플래너

유니버설 인박스 + 커맨드 바 타임블로킹

레이아웃
태스크 리스트(좌) + 캘린더(우) 2패널 분할, 리스트→캘린더 드래그. 플래닝 뷰는 Inbox + Today/This Week/This Month 3칼럼.
Today 개념
모든 입력(메일·Slack·노션·브라우저 탭)이 단일 인박스로 수렴, Cmd+K 커맨드 바로 생성·스누즈·이동. 자동 트리거되는 플래닝/셧다운 리추얼.
모범 사례
  • Time Slots — 태스크를 담는 컨테이너형 캘린더 블록
  • 2025–26 모바일: 아침/점심/저녁 AI 브리핑 3종
Dumply 적용
알프레도의 시간대별 브리핑(아침 계획·저녁 랩업) 알림 패턴 참고.

출처: product.akiflow.com

11

Motion

데일리 플래너

AI에 완전 위임 — 하루에 수백 번 재최적화되는 일정

레이아웃
캘린더 중심 + 우측 태스크 사이드바(자동 스케줄 토글). 잠긴 블록은 실선, AI가 옮길 수 있는 블록은 점선 테두리.
Today 개념
마감·소요시간·우선순위만 주면 AI가 빈 시간에 배치하고 하루 종일 재조정. 미완료는 조용히 다음 슬롯으로 자동 이월, 마감 위험은 며칠 전 선제 경고.
모범 사례
  • 점선/실선 테두리 — "AI가 움직일 수 있는 것"의 시각적 신뢰 신호
  • 수동↔AI 제어의 원클릭 전환 토글
Dumply 적용
알프레도 제안 항목에 점선 스타일 적용 — "아직 확정 아님"을 시각 언어로.

출처: usemotion.com

12

Amie

데일리 플래너

출처: help.headspace.com · kimp.io

교차 분석 — 30개 사례를 관통하는 7개 패턴

P1 · 보편 스켈레톤: 접이식 사이드바 + 메인 (+온디맨드 우측 패널)

30개 전부가 이 뼈대의 변주입니다. 플래너 계열의 지배적 변형은 "태스크 큐 패널 + 캘린더 패널" 병치(Akiflow·Amie·Reclaim·Routine·Sunsama). 모바일 전환 시 사이드바는 최대 5항목 바텀 탭바(44×44pt 터치 타깃)로 변환 — Vercel·Habitica·Duolingo가 실증.

P2 · "오늘"의 두 철학과 그 종합

시스템 계산형(Todoist·Linear·Monday·ClickUp·Motion·Reclaim)은 유지비가 낮지만 주도감이 약하고, 사용자 서약형(Any.do·Sunsama·Trello Planner·ClickUp LineUp)은 주도감이 강하지만 매일 의식이 필요합니다. 2025년의 종합형은 "AI가 제안 → 사용자가 원탭 승인"(Any.do Smart Suggestions, GitHub 에이전트 모듈) — Dumply의 알프레도 트리아지가 정확히 이 자리에 있습니다.

P3 · 오버듀 전략 스펙트럼

일괄 리스케줄(Todoist) ↔ 최상단 강제 병치(ClickUp·Monday) ↔ 자동 무음 이월(Motion·Reclaim) ↔ 제안으로 격리해 죄책감 제거(Any.do). 브레인덤프 앱은 미룬 항목이 필연적으로 쌓이므로, 격리+제안 모델이 아니면 홈이 죄책감 게시판이 됩니다.

P4 · 개인화는 가드레일과 함께

자유 캔버스는 없습니다. Notion(섹션 show/hide/reorder), Stripe(큐레이션된 위젯 피커), GitHub(모듈+필터), Asana/ClickUp(위젯 그리드지만 여전히 카탈로그 기반). Asana·ClickUp 포럼엔 "더 열어달라"는 요청이 상존 — 위젯 홈은 원하지만 잘 만들기 어렵다는 증거.

P5 · 신뢰의 시각 언어: 점선 vs 실선

AI가 옮길 수 있는 블록은 점선, 확정은 실선 — Motion과 Reclaim이 독립적으로 수렴한 패턴. AI 제안을 다루는 모든 UI의 사실상 표준이 되고 있습니다.

P6 · 딜라이트 스펙트럼과 빈 상태

한쪽 끝 Linear(축하 제로, 속도가 보상) ↔ 반대쪽 Asana(유니콘)·Duolingo(풀스크린 축하). 가장 많이 복제된 단일 패턴은 Superhuman의 '비운 인박스 = 매일 다른 사진 + 스트릭'. 빈 상태는 비용이 낮고 기억에 남는 차별화 지점입니다.

P7 · 2025 신모듈: "내 AI가 한 일"

GitHub(에이전트 태스크 모듈 + 카드 내 액션), Notion 3.0(Agents 섹션), Height(자동 트리아지 결과 검토). 홈의 역할이 '내가 할 일'에서 'AI가 해둔 일의 검토'로 확장 중 — 단, GitHub의 롤백이 보여주듯 기존 사용자의 홈을 바꿀 땐 탈출구가 필수.

Dumply PWA 권장 설계안

30개 사례의 교차점에서 도출한, Dumply의 성격("정리하지 말고 던져라" + 탐정 펭귄 + 웜 모노크롬)에 맞춘 구성

1 · 반응형 스켈레톤

데스크톱 (≥1024px) — 사이드바 + 2패널

알프레도 브리핑 + 스트릭

현 사이드패널 UI를 중앙 칼럼(max 520px 유지)으로 이식하고, 우측에 캘린더/타임라인 패널을 병치 — Akiflow·Amie 계열의 "큐+캘린더" 표준. 하단 라운드 필은 덤프 퀵 입력.

모바일 PWA (<768px) — 단일 칼럼 + 바텀 탭

알프레도 무대 (접기 가능)

홈·캘린더·프로젝트·설정 4탭 (≤5 규칙). env(safe-area-inset-bottom) 패딩, 44pt 터치 타깃, overscroll-behavior로 당겨서 새로고침 제어.

2 · 알프레도의 역할 — 장식에서 시스템 보이스로

홈 상단 무대 (Finch 26) + 접기 (Finch의 교훈)

홈 상단에 알프레도 브리핑 카드: 인사(시간대별, Notion 17) + "밤새 분류해둔 것 N건" + 오늘의 수사 진행도. 단 Finch의 산만함 교훈대로 한 줄 헤더로 접을 수 있게.

상태 머신 (Duolingo 25) — 단, 친절 모드 (Finch 26)

알프레도 표정: 만족(Today 비움) → 수사 중(진행) → 궁금(덤프 쌓임). Duolingo식 죄책감 압박은 배제 — 방치해도 아프거나 화내지 않고, "단서가 쌓였어요" 수준의 호기심으로 표현.

시스템 전역 감정 전달자 (Headspace 30)

빈 상태·오프라인 배너·스켈레톤 로딩·오류·PWA 설치 유도 카드 전부를 알프레도가 프론트. 특히 설치 유도는 beforeinstallprompt를 잡아 첫 스트릭 달성 직후 알프레도 카드로 노출 (web.dev 권장 컨텍스추얼 타이밍).

보상형 빈 상태 (Superhuman 19 + Todoist 01)

Today를 비우면 "사건 종결" — 매일 다른 알프레도 일러스트 한 컷 + 주간 스트릭. 완료 순간엔 Asana(03)식 랜덤 variant 축하를 Must 항목에만 절제 적용.

3 · Today 보드 — "AI 제안, 사용자 승인" 종합형

트리아지 큐 (Linear 06 + Any.do 08)

덤프는 즉시 Today로 가지 않고 알프레도의 분류 대기열로. 아침 홈에서 MoSCoW 제안을 원탭 수락/미루기 — 오버듀도 자동 유입 대신 여기로 격리(안티-길트). 모바일에선 Slack Catch Up(18)식 스와이프 트리아지.

MoSCoW를 상태 언어로 (Monday 05 + Vercel 21)

색은 MoSCoW 기능색만 사용하고 나머지는 웜 모노크롬 유지 — 이미 tokens.css의 원칙. Must/Should 섹션 헤더는 빈 섹션일 때 숨김(Linear 06).

제안엔 점선, 확정엔 실선 (Motion 11 · Reclaim 14)

알프레도가 제안한 미확정 항목은 점선 보더 카드로 — 승인하면 실선으로 확정되는 마이크로 전환이 신뢰와 딜라이트를 동시에.

오늘의 3가지 (ClickUp LineUp 04) + 시간대 섹션 옵션 (Habitify 29)

보드 최상단에 알프레도 추천 3개 고정. 캘린더 연동 시 아침/오후/저녁 섹션에 이벤트와 인터리브.

4 · PWA 기술 체크리스트 (web.dev 기준)

셸과 오프라인

앱 셸(내비+레이아웃+스켈레톤)은 cache-first, 태스크 데이터는 stale-while-revalidate. 오프라인에서도 Today 조회·체크오프는 동작하고 백그라운드 싱크로 큐잉 — Todoist(01)가 증명한 카테고리 기대치. 오프라인 배너는 알프레도가 안내.

설치성

manifest(512px 아이콘, display: standalone, theme_color=웜 배경) + 서비스 워커 + HTTPS. iOS는 프롬프트 이벤트가 없으므로 수동 "홈 화면에 추가" 안내 분기.

앱답게 느껴지기

viewport-fit=cover + safe-area 인셋(바텀 탭바 필수), overscroll-behavior-y: contain, 스켈레톤 → 콘텐츠 부드러운 스왑, 낙관적 UI + 실행취소(Superhuman 19). 성능 예산: Twitter Lite 레시피(1MB 이하 셸, 재방문 3초 미만 부팅).

키보드 레이어 (데스크톱 웹)

Cmd+K 팔레트(Linear 06 · Notion Calendar 13)와 자연어 퀵애드(Todoist 01 · Routine 16)는 프리미엄 웹앱의 테이블 스테이크. 최소한 n=새 덤프, 1–4=MoSCoW 지정부터.
