Dumply Design System Proposal · v0.1 · 2026-07

Dumply PWA 디자인 시스템 제안
— "AI 티" 나지 않는 토큰 시스템

30개 사례 리서치(디자인 리서치 보고서)에서 확인한 타사 디자인 시스템 — Vercel Geist, Stripe, Linear, Amie, Craft — 의 결정 원리를 빌려, Dumply의 기존 tokens.css를 PWA용 3계층 토큰 시스템으로 확장합니다. 목표는 하나: 웜 아이덴티티는 지키되, "AI가 만든 것 같은" 디자인의 관습적 마커와 토큰 수준에서 갈라서는 것.

구현 초안: docs/tokens-pwa-draft.css · 이 문서 자체가 제안하는 토큰으로 렌더링되며 라이트/다크를 모두 지원합니다.

1 · 진단 — "AI 티"는 정확히 어디서 나는가

생성형 디자인이 수렴하는 관습적 마커와, Dumply의 현재 위치

가장 먼저 인정할 것: Dumply의 웜 크림 배경(#F3F1EB)은 AI 생성 디자인의 최다 빈출 클리셰(웜 크림 #F4F1EA + 세리프 디스플레이 + 테라코타 액센트)와 위험할 만큼 가깝습니다. 하지만 Dumply를 구하는 것은 배경색이 아니라 그 위의 결정들입니다 — 세리프도 테라코타도 없고, 액센트가 모노크롬(에스프레소 차콜)이며, 유채색이 기능에만 묶여 있습니다. 이 방어선이 우연이 아니라 규칙이 되도록 토큰으로 강제하는 것이 이 제안의 요지입니다.

AI 생성 디자인 마커Dumply 현재토큰 시스템의 방어 규칙
웜 크림 + 세리프 + 테라코타 조합크림만 해당세리프 디스플레이 금지(Pretendard 단일), 유채 액센트 도입 금지 — 액센트는 듄 램프 900번
보라→파랑 그라데이션 히어로없음그라데이션 전면 금지 (기존 차콜 액센트 그라데이션 1종만 예외로 등재)
균일한 rounded-lg 모서리부분 해당반경을 역할 위계 스케일로 고정: 칩 999 / 컨트롤 10 / 카드 14 / 시트 24 / 무대 28
균일 box-shadow 카드그림자 거의 없음그림자 금지 — 깊이는 서피스 온도 사다리(들어감<바닥<올라옴)와 1px 보더로 (Stripe·Geist)
이모지 섹션 마커·스톡 일러스트알프레도 단일 세계관UI 일러스트는 알프레도 캐릭터 시스템만. 이모지는 사용자 콘텐츠 영역 한정
장식용 유채색 (컬러풀 위젯·배지)기능색 원칙 있음유채색 = MoSCoW·상태·캘린더 밴드만. 결정 트리로 강제 (§4)
다크 모드 = 단순 명도 반전다크 부재같은 웜 hue의 저명도 사다리를 별도로 구축, 기능색은 채도 음소거 변형 (Linear·Stripe)
모든 것 중앙 정렬 + 진입 애니메이션 남발좌측 정렬 기조모션은 상태 전환 3종(hover/전개/승인·축하)에만. 진입 애니메이션 금지

2 · 결정 원칙 — 타사 시스템에서 빌린 것

리서치 보고서의 사례 번호를 병기. 각 원칙은 §5의 토큰으로 구현됩니다.

색은 의미에만, 크롬은 모노크롬

Geist의 "색은 상태 점·링크·오류에만"을 Dumply 문법으로: 유채색이 보이면 그것은 반드시 MoSCoW 우선순위이거나 캘린더 이벤트다. 이 일관성 자체가 수제(手製)의 인상을 만든다.

근거: Vercel Geist (사례 21) · Stripe 액센트 1색 원칙 (20)

깊이 = 온도 사다리, 그림자 금지

Stripe는 흰색→#f8fafd→#e5edf5 틴트 단계로 깊이를 만든다. Dumply 기존 tokens.css의 "들어감<바닥<올라옴" 서피스 사다리와 동일 사상 — 이를 5단계 시맨틱 토큰으로 승격하고 box-shadow를 린트로 차단.

근거: Stripe (20) · 기존 tokens.css 주석의 L90–98.4 사다리

다크는 반전이 아니라 재구축

Linear는 LCH 색공간에서 표고(elevation)별로 지각적으로 등간격인 테마를 생성한다. Dumply 다크는 라이트 값의 반전이 아니라 같은 웜 hue(≈75–85)의 저명도 사다리(#14110D→#2B261F)를 따로 짓고, MoSCoW 색은 채도를 낮춘 다크 변형을 쌍으로 정의한다.

근거: Linear LCH 테마 (6) · Stripe 다크 상태색 음소거 (20)

모션은 물리, 순간은 하나

Amie처럼 스프링 이징을 쓰되 남용하지 않는다: 스프링은 "AI 제안 승인(점선→실선)"과 "완료 축하" 두 순간에만. 나머지는 120/200ms ease-out. 진입 애니메이션은 금지 — 속도가 보상이라는 Linear의 절제를 기본값으로.

근거: Amie (12) · Linear (6) · Superhuman 100ms 예산 (19)

점선 = 제안, 실선 = 확정

Motion과 Reclaim이 독립적으로 수렴한 신뢰 언어를 토큰화: --dumply-ai-border-style: dashed. 알프레도가 제안한 모든 것은 점선으로 태어나 사용자의 승인으로 실선이 된다. "AI 기능이 있는 앱"이 아니라 "조수가 있는 앱"으로 읽히게 하는 핵심 장치.

근거: Motion (11) · Reclaim (14)

캐릭터가 유일한 장식

Craft가 커버 이미지로, Headspace가 블롭 캐스트로 하는 일을 Dumply는 알프레도 하나로 한다: 빈 상태·오프라인·로딩·축하·설치 유도 전부. 범용 일러스트·아이콘 팩·이모지 마커가 낄 자리를 없애면 생성형 디자인의 익명성이 사라진다.

근거: Craft (24) · Headspace (30) · Duolingo/Finch (25·26)

3 · 토큰 아키텍처 — 3계층

기존 tokens.css(1계층 플랫 구조)를 호환 유지하며 확장

① Primitive   --dune-0 … --dune-950   웜 듄 램프 13단계 (단일 hue, 기존 실측값이 앵커)
              --fn-*, --fn-*-dark      기능색 라이트/다크 쌍
              --band-*                 캘린더 밴드 파스텔 (이벤트 전용)
                 ↓  컴포넌트에서 직접 참조 금지
② Semantic    --dumply-surface-{sunken|soft|base|raised|overlay|active}
              --dumply-ink-{primary|body|secondary|placeholder}
              --dumply-moscow-*, --dumply-ai-*
              --dumply-radius-*, --sp-*, --fs-*, --motion-*
                 ↓  다크 테마는 이 계층에서만 재정의
③ Component   --card-*, --suggestion-*, --tabbar-*  (필요한 곳만)

규칙: 컴포넌트 CSS는 다크 모드를 몰라야 합니다. @media (prefers-color-scheme)과 [data-theme] 분기는 토큰 파일에만 존재하고, 컴포넌트는 시맨틱 토큰만 소비합니다. 기존 사이드패널의 --dumply-bg·--dumply-surface 등은 시맨틱 계층의 별칭으로 유지되어 마이그레이션 없이 공존합니다.

기능색 — 웜 지면에 맞춘 템퍼링 + 다크 음소거 쌍

현재 tokens.css의 iOS 시스템색(#FF3B30·#FF9500)은 채도가 높아 웜 지면 위에서 "기성품" 인상을 줍니다. 온도를 맞춘 템퍼링 값과, Stripe 원칙대로 다크에서 소리치지 않는 음소거 변형을 쌍으로 제안합니다.

must #D6493C · 다크 #E06A5F should #C97C1E · 다크 #DE9B4A could = ink-secondary (무채) won't = placeholder (무채) success #3F8F5F · 다크 #5FB585 info #4A7DC9 · 다크 #7AA3DE

색 사용 결정 트리 (린트 가능한 형태)

  1. 이 요소가 우선순위나 상태(MoSCoW·성공·오류·경고)를 전달하는가? → --dumply-moscow-* / 상태 토큰
  2. 캘린더 이벤트인가? → --band-* 파스텔 (이벤트 밖 사용 금지)
  3. 알프레도의 제안(미확정)인가? → 점선 보더 + --dumply-ai-*
  4. 그 외 전부 → 듄 램프. 예외 없음.

6 · 형태 · 타이포 · 모션 스케일

반경 위계

chip 999 · control 10 · card 14 · sheet 24 · stage 28 — 큰 것일수록 둥글게. 균일한 rounded-lg가 만드는 "생성물" 인상을 위계로 대체.

간격

4px 베이스 스케일(--sp-1…--sp-12). 형제 요소 간격은 flex/grid gap으로만 — 마진 겹침 금지.

타이포

Pretendard 단일 패밀리 유지(세리프 디스플레이 금지). 기존 스케일 유지 + PWA 그리팅 전용 --fs-display: 28px. 숫자 정렬 구간엔 tabular-nums.

모션 3단

quick 120ms(hover/press) · standard 200ms(전개/접힘) · emphasis 320ms + spring(제안 승인·완료 축하 한정). prefers-reduced-motion에서 전부 0ms.

7 · 거버넌스 — 규칙을 규칙답게

Stylelint(declaration-property-value-allowed-list)로 CI에서 강제 가능한 6칙

  1. raw hex 금지. 컴포넌트 CSS는 시맨틱 토큰만 소비한다.
  2. box-shadow 금지. 오버레이 서피스 1곳 예외. 깊이는 사다리로.
  3. 유채색 배경 금지. MoSCoW 칩·캘린더 밴드 예외.
  4. border-radius는 스케일 값만. 임의 반경 금지.
  5. 그라데이션 금지. 기존 액센트 그라데이션 1종만 등재 예외.
  6. 컴포넌트 파일에 다크 분기 금지. 테마는 토큰 계층의 책임.
마이그레이션 경로: ① docs/tokens-pwa-draft.css를 PWA 셸에 로드 (기존 --dumply-* 이름은 별칭으로 호환) → ② 신규 컴포넌트부터 시맨틱 토큰 사용 → ③ 사이드패널 CSS의 raw hex를 점진 치환 → ④ Stylelint 규칙 활성화. 기존 확장 UI는 한 줄도 깨지지 않습니다.
